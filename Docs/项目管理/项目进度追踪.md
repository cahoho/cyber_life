## 1. 状态口径

| 状态 | 含义 |
| --- | --- |
| 已实现 | 代码和接口主体存在，且完成范围可由代码或现有测试证明 |
| 部分实现 | 主路径可运行，但缺少文档要求的关键能力、契约字段或验收证据 |
| 未实现 | 未发现对应实现 |
| 待人工验收 | 实现可能存在，但必须在团结引擎、Play Mode 或固定场景中验证 |

完成状态只认三层证据：

```text
代码实现 + 契约一致 + 对应验收项通过
```

仅有代码、仅有截图或“看起来能跑”都不能把里程碑标为完成。

## 8. 架构稳定性与风险

### 已保持的边界

1. Unity 主线程不等待 Python；取帧使用异步 GPU 回读。
2. 快视觉与 VLM 已分线程、分频率，VLM 不直接覆盖快几何。
3. 射线通行性由确定性几何生成，语言模型不能写坐标或网格。
4. 感知身份使用视觉 `track_id`，没有把 Unity 实例 ID送给快照。
5. 服务不可用、模型不可用和 VLM 未配置均有降级路径。

### 需要控制的风险

| 优先级 | 风险 | 影响 | 建议 |
| --- | --- | --- | --- |
| P0 | 文档基线与工程基线不一致 | 后续按错误版本开发，身体/学习阶段接口失效 | 确认采用团结 1.10 还是当前 1.11，并核对 RigGraph、ML-Agents 依赖 |
| P0 | `Belief` 未实现但总览曾标“Phase 1 已完成” | 后续 LookAt 无法可靠引用世界目标 | 完成 `BeliefStore` 后再宣布 Phase 1 通过 |
| P0 | 契约由 C# 手写 JSON + Python dataclass 双维护 | 字段漂移，联调错误难定位 | 增加共享 JSON fixture 和双端契约测试 |
| P0 | 运行时可能通过场景树、目标 Transform 或 WorldTruth 作弊 | Human 失去独立性，视觉/Belief/物理闭环均可被绕过 | 只允许传感器、感知、Belief、BodyState 进入决策；Truth 仅供隔离 Verifier/Debug |
| P1 | `PerceptionTransport` 同时负责传输、门限、UI 和问答 | 后续扩展容易形成耦合巨石 | 小步拆成传输、结果门限、Overlay/查询适配器 |
| P1 | 场景状态与长期记忆同名 | “Memory”语义混乱 | 后续区分 `PerceptionCache` 与正式 `Agent Memory` |
| P1 | 仔细理解只有最新帧，无关键帧/请求配对 | 无法复现触发原因，无法满足契约 | 实现 `slow.request` + 关键帧缓冲 |
| P2 | 通行网格没有时序融合 | 单帧遮挡/噪声导致净空跳变 | Phase 3 前增加多帧确认，不急于做路径规划 |

## 9. 下一阶段工作顺序

保持“每次修改不宜过多”，按以下顺序小步推进。上一项未形成可验证结果前，
不提前开启下一大块。

### P0-1：冻结工程与契约基线

- 确认团结引擎、RigGraph、ML-Agents 的实际版本。
- 对齐 `ProjectVersion.txt`、`Packages/manifest.json`、理论文档和落地方案。
- 为 `FrameEnvelope` / `PerceptionSnapshot` 建立一组双端共享 JSON fixture。
- 这一步原则上不改业务行为。

完成证据：文档一致；Python 与 C# 都能解析同一组正例/反例。

### P0-2：完成 Phase 1 Belief 最小闭环

- 新增独立 `BeliefStore`，不并入 `PerceptionTransport`。
- 只从有效快照和视觉事件更新，不读取 WorldTruth。
- 实现 `visible → uncertain → unknown`、时间衰减、位置跳变保护和基本事件。
- 补充纯 C# 可测试核心与 Unity Test Framework 用例。

完成证据：F1～F4 有自动化或固定场景报告。

### P0-3：补齐时序、遥测与固定验收

- 统一 `telemetry.event` JSONL；记录 capture/RTT/infer/stale/dropped。
- 增加固定场景和一条命令生成 `report.json`。
- 按 A～G 输出实测值，而不是人工主观判断。

完成证据：Phase 1 A～G 全部有通过/不通过与数据。

### P1-1：加固仔细理解

- 实现 `slow.request`、`request_id`、关键帧缓冲和冷却/预算。
- 保持 VLM 独立线程，不影响快路径。
- 对错误码、超时、畸形输出和 6 次/分钟上限做测试。

### P1-2：补齐 Phase 1 感知增强验收

- 完成离线、VLM、性能三组验收。
- 记录通行网格大小、计算耗时、遮挡盲区样例。
- 明确“单帧建议”与 Phase 3 路径规划的边界。

### 阶段门

只有 Phase 1 的 A～G 通过后，才进入正式 Phase 2 方案编写与 LookAt/Reach
实现。Phase 2 不得绕过 `BeliefState` 直接读 Unity WorldTruth。

### 独立性验收门

每个涉及目标发现、注视、移动或抓取的迭代都必须保留：

1. **无真值运行**：关闭 WorldTruth、Debug 面板和对象查找接口后仍能工作。
2. **无身份运行**：隐藏对象名称/实例 ID/目标引用，只能使用视觉 `track_id` 与 Belief。
3. **随机位置运行**：改变目标位置并重新开始，Human 必须重新观察，而不是沿用硬编码坐标。
4. **错误信念运行**：目标移动但 Human 未看见时，Skill 不得瞬移或即时更新到真值位置。
5. **失效降级运行**：传感器丢失、目标过期或置信度不足时返回结构化失败码，不读取真值补偿。
