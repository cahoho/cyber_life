# Phase 1 感知增强：通行性、场景问答与地点理解

> 编号说明：本文件是 **Phase 1 的感知增强子计划**，不是理论路线图中的
> Phase 2（LookAt / Reach / Grasp）。文件名作为历史兼容保留；项目实际状态见
> `Docs/项目管理/项目进度追踪.md`。

> 目标：在现有 RGB 取帧与 YOLO 检测链路上，补齐“哪里能走、场景里有什么、
> 我在哪里/像什么空间”三项能力，并保留无网络、无 API Key 时的降级运行。

---

## 1. 职责边界

| 能力 | 权威来源 | 输出 | 不能让谁写 |
| --- | --- | --- | --- |
| 对象存在与类别 | 快理解检测器 | `objects[]` | VLM 不能改写几何字段 |
| 障碍与可通行区域 | Unity 射线几何 + Python 网格化 | `navigation[]` | VLM 不能修改网格状态 |
| 位置 | Unity 相机位姿 | `camera.position` | VLM 不能猜坐标 |
| 地点类型 | 检测先验的保守提示 + 可选 VLM | `scene.place_hint` | 不能把低证据猜测写成事实 |
| 自然语言问答 | 本地结构化查询 + 可选 VLM | `/v1/query` | 不能在无画面证据时声称“看见” |

地点是**当前空间假设**，不是场景真值。可以随着转身、进入新区域和重新观察更新。

## 2. 数据流

```text
EyeCamera RenderTexture
   ├─ AsyncGPUReadback → JPEG ───────────────┐
   └─ Viewport rays → Unity Physics hits ────┤
                                              ▼
                                   FrameEnvelope + navigation
                                              │
                           ┌──────────────────┴─────────────────┐
                           ▼                                    ▼
                   Fast Vision (YOLO)                 Navigation Grid
                   objects / tracks                   traversable/blocked
                           └──────────────────┬─────────────────┘
                                              ▼
                                      PerceptionSnapshot
                                              │
                           ┌──────────────────┴─────────────────┐
                           ▼                                    ▼
                   GET /v1/state                  POST /v1/query
                   structured world view          grounded answer
                                              │
                                     optional low-rate VLM
```

快路径不等待 VLM。场景理解在独立工作线程中以“最新帧覆盖旧帧”的队列运行，
即使 API 超时，Unity 的采集和本地问答仍然可用。

## 3. 通行性实现

Unity `UnityRaycastNavigationSampler` 默认从前向相机视口发 `24 x 14 = 336`
条物理射线，记录：

```text
pixel_uv          图像中的左上原点归一化坐标
direction_camera  相机局部方向
hit_distance_m    命中距离
world_position    命中点世界坐标
world_normal      命中面世界法线
surface           floor / obstacle / overhead / unknown
```

Python 将命中点变换到“相机朝向投影到水平面”的局部坐标系：

```text
right   = camera_ground 的右方向
forward = camera_ground 的前方向
cell    = 0.5 m × 0.5 m
```

判定规则：

```text
1. 法线足够朝上，且高度 ≤ ground_y + step_height
   → traversable
2. 法线陡峭，或水平面高于允许台阶
   → blocked
3. 无命中 / 样本不足
   → unknown
4. 同一格既有地面又检测到高处障碍
   → blocked 优先
```

输出 `directions[]` 覆盖相机前方左 60° 到右 60°，每 15° 给出净空。

已知边界：

- 没有 Collider 的装饰物不会被物理射线发现。
- 透明玻璃、镜面、雨雾、软体、粒子没有真实几何时不能当作障碍。
- 射线只覆盖当前视线，背向和遮挡区域必须是 `unknown`。
- 单帧净空不是 A* 路径；真正移动前仍需连续帧确认与路径规划。

## 4. 地点理解

本地模式根据检测类别给保守提示：

```text
vase / potted plant / bench / person / suitcase
  → 展馆或公共大厅（候选）

book / laptop / keyboard / mouse / chair / desk
  → 书房或办公室（候选）
```

候选证据不足时返回“未知”，置信度为 `0`。配置 VLM 后，图片与结构化观测一起
传给场景理解，输出：

```json
{
  "scene_summary": "一个有展台、绿植和开放通道的公共空间。",
  "place_type": "展馆或公共大厅",
  "place_confidence": 0.72,
  "notable_events": [],
  "uncertainties": ["无法确认展台所在的具体展厅名称"],
  "visible_landmarks": ["弧形展台", "大型绿植", "开放通道"]
}
```

`place_type` 和自然语言描述可以随视角更新；`camera.position` 和通行网格始终由
确定性模块提供。

## 5. 问答接口

请求：

```http
POST /v1/query
Content-Type: application/json

{"question":"场景里有没有桌子？"}
```

响应：

```json
{
  "question": "场景里有没有桌子？",
  "answer": "检测到 1 个相关目标：dining table。",
  "grounded": true,
  "confidence": 0.81,
  "evidence": ["objects[].label"],
  "source": "fast_state",
  "source_frame_id": 1021
}
```

`source` 用于区分回答来源：

- `fast_state`：本地确定性数据，可离线。
- `vlm`：图片语义理解，可能受网络与模型幻觉影响。
- `state`：还没有任何帧。

配置 API Key 后，复杂问题走 VLM；超时或输出不合法时回退到本地结构化问答，
并在 `/v1/state` 的 `last_query_error` 中保留失败码。

## 6. API Key 与安全

推荐由本机 `perception_service` 代理 DeepSeek：

```text
Unity → localhost:8710 → DeepSeek Responses API
```

这样 Key 不写入 Unity 客户端，也不会进入 WebGL 构建、玩家设备或帧文件。

```powershell
$env:SEMANTIC_PROVIDER = "deepseek"
$env:DEEPSEEK_API_KEY = "<your-api-key>"
$env:DEEPSEEK_MODEL = "deepseek-flash"
$env:DEEPSEEK_BASE_URL = "https://api.deepseek.com"
cd Tools\perception_service
.\run.ps1
```

`deepseek-flash` 是 DeepSeek 官方模型标识，当前对应
`DeepSeek-V4.1-Flash-1017`。服务同时支持同目录下的 `.env.local`，该文件
已被 Git 忽略。

要求：

1. Key 只保存在服务端环境变量、密钥管理器或 Git 忽略的 `.env.local`。
2. 不把 `.env`、Key 和完整帧日志提交到 Git。
3. 发布环境应加鉴权、请求配额与帧数据保留策略。
4. 不把 VLM 的坐标、距离、物体框写回几何字段。
5. 不能确认时允许回答“不确定”，不要用语言流畅度替代视觉证据。

## 7. 验收

### 7.1 离线链路

- 无 API Key 启动服务，`/health` 返回 `vlm_configured=false`。
- Unity 进入 Play Mode 后，约 1 秒内 `/v1/state` 出现最新帧。
- 画面中绿点来自射线命中地面，红点来自障碍。
- 关闭服务后 Unity 继续渲染和采集，不出现主线程卡死。
- `/v1/query` 可回答“有没有某物”“前方是否通行”“我在哪里”。

### 7.2 VLM 链路

- 设置 Key 与可用图片模型后，`/health` 返回 `slow_backend=vlm:<model>`。
- 首帧后约一个推理周期内，`/v1/state.semantic.place_type` 出现结果。
- VLM 失败不改变 `objects[]`、`camera` 和 `navigation`。
- 输出包含 `uncertainties`，且没有改写坐标与通行网格。

### 7.3 量化指标

```text
navigation 样本数 ≤ 336 / 帧
navigation 序列化大小 ≤ 64 KB / 帧
通行网格输出额外计算 p95 ≤ 15 ms
遮挡盲区必须标 unknown
本地问答 p95 ≤ 20 ms
VLM 超时不阻塞采集
```
